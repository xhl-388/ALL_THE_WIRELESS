# Wi-Fi OFDMA

**OFDMA（Orthogonal Frequency-Division Multiple Access，正交频分多址）**把一个 Wi-Fi 信道中的子载波分组为资源单元（RU，Resource Unit），再由 AP 将不同 RU 分配给不同终端。这样，多个终端可以在同一传输时段、同一信道上使用不同的频率资源。

Wi-Fi 6（IEEE 802.11ax）引入 OFDMA。它的主要价值是改善多个终端同时通信时的资源利用率和调度效率，尤其适用于许多终端传送较短数据的场景；它不保证单个终端的峰值速率一定提高。

## 从 OFDM 到 OFDMA

Wi-Fi 使用的 [[OFDM]] 将信道拆分为许多彼此正交的子载波，并用它们传输数据。传统 OFDM 的一个传输机会通常由一个终端使用；OFDMA 则把子载波分组，使 AP 能在同一传输时段向多个终端分配不同的子载波组：

```text
信道中的子载波： | | | | | | | | | | | | | | | | ...
传统 OFDM：       |       一个终端使用整组资源       |
OFDMA：           | RU 给 A | RU 给 B | RU 给 C | ... |
```

这些子载波组称为 **RU（Resource Unit，资源单元）**。RU 可以有不同大小；例如 Wi-Fi 6 中常见以子载波数表示的 26、52、106、242-tone RU。较大 RU 可承载更多数据，较小 RU 可用于数据量较少的终端。具体可用的 RU 组合取决于信道带宽和标准规定的分配方式，并非任意切分。

## AP 如何安排资源

RU 不会永久分配给某个终端。AP 可以根据终端数量、待传数据量、信道条件和调度策略，在不同传输机会中重新分配：

- 大数据流可以分配较大的 RU；
- 短消息或少量数据可以使用较小的 RU；
- 多个终端可以在同一次传输中分别使用不同的 RU。

例如，一个终端正在下载较多数据，另外两个终端只有短数据需要发送，AP 可以让前者使用较大的频率资源，同时给后两者较小的 RU，而不必让每个终端都依次独占整个信道。

## 下行与上行 OFDMA

### 下行：AP 发给多个终端

AP 把不同终端的数据放在各自的 RU 上，同时发送。每个终端接收并处理分配给自己的资源。

```text
AP 同一时段发送：
  RU 1 → 终端 A 的数据
  RU 2 → 终端 B 的数据
  RU 3 → 终端 C 的数据
```

### 上行：多个终端发给 AP

多个终端不能随意同时选择 RU，否则可能发生冲突。通常由 AP 发送调度信息，指定终端、RU 和发送时机；终端按调度在分配的资源上发送，AP 再接收这些信号。由于多个终端同时发射，时间和频率同步很重要；同步误差可能造成子载波间干扰。

## OFDMA 的收益与限制

OFDMA 让 AP 能更灵活地组织多个终端的传输，主要有以下收益：

- **减少排队等待**：多个终端可以在一次传输机会中各自获得资源。
- **提高短数据传输效率**：短消息、控制数据或请求不必都占用一次独立的完整信道传输机会。
- **改善高密度场景下的调度效率**：AP 可以根据不同终端的数据需求分配不同大小的 RU。

但 OFDMA 不是无条件加速：

- 终端和 AP 必须支持相应的 Wi-Fi 功能；
- 实际效果取决于终端数量、流量模式、AP 调度策略和无线环境；
- 只有一个终端传输大文件时，多用户分配资源的优势通常不明显；
- AP 和终端仍需承担信令、同步及协议开销。

## OFDMA 与 MU-MIMO

二者利用不同维度区分用户：

| 技术 | 区分维度 | 直观理解 |
|---|---|---|
| OFDMA | 频率（不同子载波组 / RU） | 将信道分成不同频率资源，分配给多个终端 |
| MU-MIMO | 空间（不同天线和信道特征） | 利用多天线同时形成多路空间数据流 |

Wi-Fi 6 可以在合适的情况下结合 OFDMA 和 MU-MIMO。OFDMA 负责频率资源分配，MU-MIMO 利用空间维度；具体调度取决于 AP、终端能力和信道情况。参见 [[OFDM]]。
