# Wi-Fi 信道接入：CCA、NAV 与 BSS Color

Wi-Fi 设备通常不能直接在有数据时发送，而要先判断无线媒介是否可用，并与其他设备竞争发送机会。**CCA 判断物理媒介状态，NAV 保存虚拟载波侦听的预约时间，EDCA / 退避决定何时开始新的竞争式发送；BSS Color 为 Wi-Fi 6 的空间复用判断提供 BSS 分类信息。**

> [!note] 范围
> 下文先用常见的**单链路、基础设施网络、EDCA 竞争式接入**建立模型。ACK、CTS、Trigger 响应等受保护的帧交换不等同于新的 EDCA 竞争；多链路、宽信道、空间复用和特殊帧有额外规则。示意图中的时间与宽度不按实际比例绘制。

## 1. 为什么 Wi-Fi 需要先侦听？

同一信道由多个 AP 和 STA 共享。若两个设备同时向同一个接收机发送，信号可能在接收端互相干扰。设备通常不能像传统有线以太网的 CSMA/CD 那样，一边正常发送一边可靠检测远端接收机是否发生碰撞。

因此，Wi-Fi 常用 **CSMA/CA（Carrier Sense Multiple Access with Collision Avoidance，载波侦听多址 / 碰撞避免）**：先侦听媒介，再通过等待和随机退避降低同时发送的概率。它是**避免**碰撞，不是保证零碰撞。AP 和终端都可能需要竞争信道。

### 普通竞争式发送的简化流程

```text
有数据等待发送
   ↓
检查物理 CCA 与相关 NAV
   ├─ 不能接入 → 等待
   └─ 可以接入 → 连续空闲 AIFS → 执行 / 恢复随机退避
                                           ↓
                             期间再次变忙 → 冻结退避
                                           ↓
                                条件再次满足 → 等待 AIFS 后继续
                                           ↓
                                    退避到 0 → 发送
                                           ↓
                              单播通常等待 ACK / Block ACK
```

**“可以开始竞争”不等于立即发送**：即使信道当前空闲，通常还需要满足帧间间隔和退避等规则。ACK / CTS 等直接响应通常在 SIFS 后发送，不需要重新进行一轮普通 EDCA 竞争。

## 2. CCA：物理载波侦听

**CCA（Clear Channel Assessment，空闲信道评估）**是 PHY 对无线媒介状态的评估。PHY 将忙 / 空闲等状态报告给 MAC，供信道接入使用。常见理解可以分为两类检测：

| 检测思路 | 观察什么 | 作用与限制 |
|---|---|---|
| Wi-Fi 信号 / 前导检测 | 能否识别适用的 802.11 前导或信号 | 可识别存在 Wi-Fi 传输；检测到前导不等于整个帧都能正确解码 |
| 能量检测（ED） | 接收带宽内的 RF 能量是否超过相应门限 | 非 Wi-Fi 信号、不可解码的 Wi-Fi 信号等也可能使媒介被判忙；能量检测本身不识别发送者 |

具体检测条件和门限取决于 PHY、信道带宽、帧类型、设备能力、标准规则及设备配置。**接收机灵敏度、CCA 检测门限、噪声底和 RSSI 是不同概念**：一个设备能解调多少速率，不等于它对所有信号使用同一个 CCA 门限。参见 [[Receiver Metrics]]。

### 宽信道时看哪里？

在 40 / 80 / 160 MHz 等宽信道操作中，设备需要遵守**主信道接入规则**以及其他子信道的可用性检查。某个子信道繁忙时，实际能否发送、能使用多宽的带宽或能否使用 puncturing，取决于 PHY、规定的信道组合和设备能力；不能把单个 RSSI 读数直接当作整条宽信道的接入结果。

## 3. NAV：虚拟载波侦听

**NAV（Network Allocation Vector，网络分配向量）**是设备维护的本地时间状态。设备接收到符合相应规则的帧时，可根据该帧的 **Duration** 等信息更新 NAV，表示预期后续帧交换还需要占用多久。

```text
设备听到有效的预约信息 → 设置 / 更新 NAV → 计时到期前，普通竞争发送通常推迟
```

例如 A 向 AP 发送 RTS，AP 回复 CTS。能听到有效 RTS 或 CTS 的其他设备可按规则更新 NAV，为后续数据和确认交换让出时间。NAV 是每个设备根据自己接收到的信息维护的，**不是 AP 发放的一把全网锁**；不同设备能听到的帧可能不同。

### NAV 和 CCA 可以不一致

| 物理状态 | NAV | 普通竞争发送的直观结果 |
|---|---|---|
| 物理忙 | 已到期 | 通常仍要等物理状态允许接入 |
| 物理空闲 | 未到期 | 通常仍要等待虚拟预约结束 |
| 物理允许接入 | 已到期 | 还需满足相应 AIFS、退避等条件 |

这是普通竞争视角；已经属于受保护帧交换的直接响应等有各自规则。NAV 的设置、延长、复位和例外条件依帧及标准而异，不能把每个 Duration 字段都解释为同一种预约。

**NAV 与退避计数不同**：NAV 表示剩余预约时间，按实际时间流逝；物理信道忙并不会让 NAV 像退避计数一样冻结。退避计数只在满足空闲条件的退避时隙递减。

### Wi-Fi 6 的两个 NAV

802.11ax 引入区分 **intra-BSS NAV** 和 **basic NAV** 的机制，分别处理本 BSS 与其他相关帧所建立的预约状态，避免把所有预约都混成一个计时器。它们的更新、复位及空间复用交互有具体规则；**不能简单理解为“看到邻居的颜色就清空所有 NAV”**。不同代际设备和帧格式的处理也可能不同。[参考：802.11ax 高效率 WLAN 教程](https://doi.org/10.1109/COMST.2018.2871099)

## 4. AIFS、SIFS 与随机退避

### 帧间间隔

**SIFS（Short Interframe Space）**用于某些紧接在前一帧后的直接响应，例如数据后的 ACK、RTS 后的 CTS；具体响应规则取决于帧交换。

**AIFS（Arbitration Interframe Space）**用于 EDCA 各访问类别（AC）竞争信道。它由 SIFS 和类别相关的时隙数量构成：

$$
\mathrm{AIFS[AC]}=\mathrm{SIFS}+\mathrm{AIFSN[AC]}\times T_{slot}
$$

例如，仅为计算说明，若某 5 GHz OFDM 配置中 SIFS 为 $16\,\mu s$、时隙为 $9\,\mu s$，某 AC 的 AIFSN 取 3，则 AIFS 为 $16+3\times9=43\,\mu s$。**实际参数取决于 PHY、频段、AC 和网络配置**；发生接收错误时还可能适用 EIFS 等规则。

### 退避如何冻结和恢复？

设备按适用规则从 $0$ 到当前竞争窗口 $CW$ 中选择随机整数，作为退避时隙数。窗口越大，随机选择范围越大；不同访问类别可能有不同参数。

```text
假设选到 4：
空闲 AIFS → 4→3→2 → 信道变忙，冻结在 2
                         ↓
                  再次空闲并等待 AIFS → 2→1→0 → 发送
```

只有满足空闲条件的完整退避时隙才使计数递减；计数到 0 后按相应规则开始发送。其他设备也可能选到相同的时隙，因此退避仍不能杜绝碰撞。

发送失败后，设备通常会按规则扩大竞争窗口并重试；达到限制仍可能丢弃。不同访问类别或硬件重试链的具体行为可能不同。**没有收到 ACK 不足以单独证明发生碰撞**：数据帧损坏、ACK 损坏、干扰或接收端不可达也可能造成超时。

### EDCA 与 TXOP

**EDCA（Enhanced Distributed Channel Access）**通过不同 AC 的 AIFS、竞争窗口和 TXOP 参数提供差异化接入。较高优先级通常能更早竞争，但多个高优先级设备之间仍可能碰撞；它不是绝对时延保证。

**TXOP（Transmission Opportunity，发送机会）**是设备在规则允许的时段内使用信道进行一次或多次帧交换的机会，不一定只包含一个数据帧。例如 AP 获得 TXOP 后可以发送 Trigger，调度多个 STA 使用不同 RU 进行上行 OFDMA；AP 的调度发生在其获得的机会内，并不意味着 AP 完全不需要竞争。参见 [[Wi-Fi OFDMA]]。

## 5. BSS Color：Wi-Fi 6 如何区分本 BSS 与邻居？

**BSS（Basic Service Set，基本服务集）**在此可粗略理解为一个 AP 及其关联的 STA。相邻 BSS 使用相同或重叠信道时称为 **OBSS（Overlapping BSS）**。

Wi-Fi 6 / 802.11ax 在适用的 HE 传输中提供 **6 bit BSS Color**，辅助设备区分本 BSS 和其他 BSS 的传输：

```text
本 BSS：  AP1 / STA1，Color 5
邻居 BSS：AP2 / STA2，Color 9
```

Color **不是信道号、SSID、加密密钥，也不是全球唯一的 BSSID**。不同 BSS 可能发生颜色冲突；颜色不可用、未启用、不能正确识别或遇到不携带可用颜色的传输时，设备不能仅凭颜色作判断。

### Color 与 OBSS-PD 的关系

**OBSS-PD（OBSS Packet Detection，重叠 BSS 包检测）**与空间复用相关：在支持且满足适用条件时，设备识别到较弱的其他 BSS 传输后，可以根据相应门限和规则重新评估是否允许空间复用，并受到相应发射功率等限制。

例如只为说明 dBm 比较方向，假设某次适用的 OBSS-PD 门限为 $-72\,\mathrm{dBm}$：

- 邻居信号 $-75\,\mathrm{dBm}$ **比门限弱**；
- 邻居信号 $-65\,\mathrm{dBm}$ **比门限强**。

这个数值只是示意，**不是所有 Wi-Fi 设备的默认门限，也不是单独的发送许可**。还需要考虑是否正确识别为适用的 OBSS 帧、相关 CCA 状态、NAV、设备能力、适用规则和发送功率限制。较高的门限可能增加并发机会，但也可能增加对邻居的干扰；接收端的 SINR 和最终吞吐未必改善。

**BSS Color 只提供分类线索，不能消除 RF 干扰。**特别是 AP 在自己位置看到邻居较弱，不保证其终端在另一位置也看到同样弱的干扰。多 AP 协调与 Co-SR / Co-BF 是进一步讨论的不同机制，参见 [[Wi-Fi 8 UHR]]。[参考：Cisco 的 802.11ax 空间复用介绍](https://www.cisco.com/c/en/us/products/collateral/wireless/white-paper-c11-740788.html)。

## 6. 隐藏节点、RTS / CTS 和重传

```text
STA A ─────→ AP ←───── STA B

A 与 B 可能彼此听不到，但两者的信号都能到达 AP。
```

在这种**隐藏节点**情况下，A 和 B 各自物理侦听都可能认为空闲，却同时向 AP 发送并在 AP 处碰撞。可选的 RTS / CTS 通过发送端和接收端的控制帧传播预约信息，让能听到相应帧的其他设备更新 NAV，从而缓解部分隐藏节点问题。

RTS / CTS 不是万能保护：有设备可能听不到控制帧，非 Wi-Fi 干扰也不会遵守 NAV，而且控制帧本身有空口开销。设备是否启用以及用于哪些帧，取决于实现、配置和场景。

单播数据通常需要 ACK 或 Block ACK；聚合传输中可按 MPDU 确认。未确认的帧可能重传，但重传增加空口占用和时延；重试超过限制仍可能丢弃。组播通常没有逐帧 ACK，不能直接套用单播成功率的计算。

## 7. 排查时分别看什么？

1. **物理层**：目标频段、带宽、干扰 / 噪声、信号强度，以及设备提供的 CCA / busy 时间统计；各厂商计数器口径可能不同。
2. **MAC 层**：重传、失败、RTS / CTS、帧类型、队列及业务延迟；结合流量和统计窗口判断。
3. **空间复用**：确认设备及网络是否支持和启用了相关机制，再看邻居 BSS、颜色冲突与功率配置；不能只看颜色字段推断实际复用成功。
4. **抓包局限**：普通抓包通常看不到所有 PHY 状态，也可能漏掉损坏帧、隐藏节点的发送或 ACK；Radiotap 是驱动提供的元数据，不等于完整空口波形。参见 [[Wi-Fi PPDU]]。
